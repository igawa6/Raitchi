# Shared AOT runtime migration

Implementation update: the [full common Android runtime and both private title
producers](shared-android-integration.md) now build and pass host gates. The plan
below records the design and migration requirements; its earlier extraction and
producer tasks are implemented. Actual Thor execution/gameplay and the launcher
library UI remain pending. The working reference apps remain unchanged.

2026-10-25. Migration plan based on the pinned CPU/generator/loader sources, [runtime audit](runtime-audit.md), [module contract](module-abi.md), [plan](PLAN.md) and [current progress](progress.md). LAS and Eevee still boot through independent `libmain.so` artifacts. The [first common execution core](shared-aot-execution.md) is now implemented and tested with synthetic producers; real-game integration remains pending. Eevee's native Opus, swapchain-image handling and Android UI busy-loop fixes are preserved in its working reference. The owner reports it working and cooler after the CPU fix; this is not a controlled emulator power comparison. Shared-core work has performed no device actions.

## Foundation checkpoint before full Android integration

`native/runtime/` now supplies the common CPU identity3, dispatch/cache, both hook
mechanisms, optional profiling, nine SDK libc wrappers, immutable session layout
and an integrated layout/descriptor/dispatch setup gate. One core artifact passes
79 synthetic host scenarios in each optimized and sanitizer variant; Android
arm64 cross-linking succeeds. Twelve sampled real generated objects compile
against the common header. See the [execution results](shared-aot-execution.md),
[codegen probes](shared-aot-codegen-probes.md) and [complete legacy import
inventory](shared-aot-imports.md).

Serialized sidecar/file verification, real NSO mapping/relocation/init, OS/HLE,
adapters and renderer convergence remain open. The common core supplies15 of
the56 measured legacy runtime import names;41 still require their actual
OS/title implementations. There is no complete production `shared-aot-v1`
contract freeze or real title rebuild yet. Preserve the references while
extracting those implementations, rather than relabeling legacy game libraries.

The [Echoes source audit](echoes-source-audit.md) adds future constraints without
changing the current acceptance pair: independent module load/init order, main
larger than64MiB, five-argument SDK startup, 128-bit exclusive helpers and GPU
write visibility. The session-layout tests cover a hypothetical different module
order/size; metadata loading and Echoes execution are not enabled.

## Decisions to implement

1. **Preserve LAS Android's exact CPU cache layout.** Use one 16-byte-aligned, 66,560-byte `Cpu`: existing 1,024-byte register prefix followed by 4,096 `{ uint64_t addr; GuestFn fn; }` entries at offset1,024, stride16. Keep `GuestFn = void (*)(Cpu *)`, ARM64 assembly SIMD, and LAS's cache hash `((pc >> 4) ^ (pc >> 14)) & 4095`. Remove Let's Go's separate TLS dispatch cache from the common path. Assert every field offset, vector offset512, cache offset/stride/count, size and alignment in the shared header and a generated-library compile check. Preserve `musttail`; retain HLE/override precedence and LAS's policy of avoiding cached HLE calls. CPU objects, including thread/temporary copies, must allocate and initialize the full structure; do not merely change the public typedef.
2. **Support the two existing address profiles in one runtime.** LAS retains shift `0x6000000000`, actual window `[0x1000000000,0x1320000000)`. Eevee retains shift0, window `[0x7000000000,0x7320000000)`. One immutable `SessionLayout`, selected and checked before reservation/thread creation, supplies module bases, HLE/TLS/heap/alias/stack ranges and guest-pointer predicates. No per-title runtime compile define chooses these addresses. Generated code remains specialized for its declared profile; the shared runtime uses the selected layout. This avoids an unnecessary first-port rewrite of Let's Go's generator and embedded literals.
3. **Retain the working Android platform and renderer.** Extract from LAS Android; carry reviewed, required Let's Go HLE/NVN semantics into that one implementation. Keep its Android surface/volk/driver loading and feature negotiation. The independently booted Let's Go renderer, including its guest-memory snapshot fix, is reference evidence for required behavior; it is not a second selectable renderer binary. Renderer convergence is a later, explicit integration step after the CPU/loader seam works.
4. **One `libmain.so` initially, with both adapters built in.** Retain the SDL-required native entry/runtime SONAME and load one title library per fresh application process. Compile both adapter source sets into the identical runtime artifact; select a registry entry through validated launch metadata. Adapter extraction does not require a new adapter `.so` boundary in this milestone. Preserve attribution/licenses when copying source. Do not mutate `sources/` or the known-working reference outputs.

An unshifted full window succeeded twice in the actual Eevee Android process on Thor. That supports keeping this observed profile; it does not guarantee other zygote layouts/devices. Reserve safely without Android re-exec or destructive fixed mapping, verify the complete requested window, and refuse guest entry if unavailable. There is no runtime fallback from shift0 to LAS's shift: that needs a separately generated artifact with a matching profile. A later common shifted profile is optional work, not a prerequisite for identical runtime bytes.

## Address and hook boundaries

Split the common CPU definition/inline arithmetic from generated-code options. Implemented files are `native/runtime/aot_cpu.h` for the structure/helper semantics and `native/runtime/session_layout.h/.c` for runtime address state. The probes use producer-specific wrappers; a production generated `aot_profile.h` for the selected code's shift/SIMD/hook capabilities remains to be integrated. It must never decide common runtime constants. Canonical module and patch addresses remain in metadata; actual pointers and dispatch tables contain addresses after checked subtraction. LAS `tools/gen.py --shift` already translates analysis/images/literals while preserving canonical function/label names. Do not subtract again from guest pointers read from memory.

Convert `rt.h`/`kernel.h` layout macros and every consuming initializer into session accessors or explicit initialization. The first mechanical checklist is `main.c`, `loader.c`, `dispatch.c`, `kernel.c`, `platform/android.c`, `fnprof.c`, `nvn/cmdbuf.c`, `nvn/vulkan/device.c` and `nvn/vulkan/exec.c`. Also relocate LAS title uses in `rando.c` and `hle/{digs,miniboss,shell_spots,warp,widescreen}.c` to its adapter. Reconcile Let's Go's raw pointer-range predicates and `fnhook.c:rt_addr()` with the same interface. Constants in core graphics memory bounds must become session ranges even while preserving renderer algorithms. Merely replacing `MAIN_BASE` is insufficient.

Keep two distinct hook facilities:

| Facility | Required behavior | Migration |
| --- | --- | --- |
| LAS instruction-site `rt_hook(c, site)` |0 executes the preserved original instruction;1 handles it;2+ select generated local branch targets. Generator verifies the original instruction word. | Keep generated sites/branch targets and runtime return protocol. Adapter owns site IDs, original words and title behavior. Adding a site requires regeneration of affected generated code. |
| Let's Go `FN_ENTER(addr)` / `rt_fnhook` | A hook can handle a whole function and cause immediate return. It must run on **direct generated calls**, cached dispatch and ordinary indirect calls. `rt_call_original` bypasses the intended next entry without recursively invoking the same hook. | Keep generic registration/lookup/bypass machinery in core. Adapter owns build maps and callbacks. Test nested calls and per-thread bypass; avoid a dispatch-only replacement. |

LAS Android normally compiles `FN_ENTER` to nothing; Let's Go ABI3 requires function hooks. Freeze an explicit code-generation hook-capability mask. Initially LAS may advertise instruction hooks without function hooks, preserving its compiled fast path; Eevee advertises function-entry hooks. The runtime supports both and refuses function-hook registration for an artifact that lacks the capability. A profile that later enables LAS function hooks must recompile its affected generated objects and receive a new identity. Do not silently enable a branch in every LAS function and call that preservation of its baseline cost. Function profiling is a separate optional capability. Both generators bypass `FN_ENTER` for generated HLE forwarding wrappers; preserve and test that existing distinction.

Adapter build maps translate canonical source-build addresses to the selected canonical target build, then to actual addresses once. Remove Eevee/Pikachu tables and `g_build` decisions from generic `fnhook.c`; `rt_call_original` consumes an actual resolved address. A per-function next-entry bypass must remain thread-local. Cache entries must not hide function-entry hooks. If dispatch overrides change after caching, explicitly invalidate affected/all CPU caches; a fresh session starts with empty caches.

## Four-module loading and initialization

Adopt a validated module registry rather than LAS's fixed main/SDK fields. Accept exactly the selected profile's inventory, in order: LAS `main,sdk`; Eevee `main,sdk,subsdk0,subsdk1`. Canonical bases are `0x7000000000`, `0x7004000000`, `0x7006000000`, `0x7008000000`. These guest submodules remain necessary despite host shaderc/FFmpeg.

Verify independently supplied full32-byte NSO build IDs, complete original-file SHA-256, mapped/text ranges and generated counts. Load **all** modules before any relocation. Preserve resolution order: defined guest symbol; undefined import's host HLE; another guest module; weak-zero; reviewed unresolved stub/error. Keep HLE/service/NVN linker registries retained. Prefer each non-main module's `DT_INIT`, otherwise its init array, in SDK/subsdk0/subsdk1 order; initialize main through the existing SDK startup callback afterward. Preserve guest TLS/FP state setup. Two-module LAS follows the same loop without subsdk entries. Record observed import/proc coverage; generic return-zero stubs do not establish support.

The provisional `native/module_abi.h/.c` already distinguishes CPU identities, shifts and two/four-module metadata. `native/module_loader.h/.c` adds `RTLD_NOW | RTLD_LOCAL` and the exported **data object** `recomp_module_descriptor_v1`, not an entry getter. Wire its successful validated descriptor into the actual runtime registry before any module initialization/guest call. It is currently host plumbing, not proof of game execution. The first actual `dlopen` attempt consumes the process even on rejection; no unload/retry/reset scheme substitutes for a new Android process.

Before `dlopen`, verify the trusted local producer's sidecar schema, library hash, original module hashes, expected runtime API and generated-code contract. After `dlopen`, validate the descriptor against that independent profile. Sidecar expectations must not be copied from the descriptor. Constructors can already run at `dlopen`; this is trusted local code loading, not hostile-library isolation.

## Executable contract and ELF policy

Name the new execution contract `shared-aot-v1`, independently of upstream `GAMELIB_ABI1/3` and provisional metadata version1. Its implemented CPU identity3 explicitly reserves `excl_hi` at336 while retaining LAS's cache layout; 128-bit helpers remain pending. Keep the current sized metadata descriptor while binding its missing execution requirements in a strictly versioned sidecar: runtime API version/contract digest, full generated-code identity, SIMD mode, hook/profiling capability mask, target/API, generator/options and the actual compiled-library SHA-256. The descriptor declares the common cache CPU identity; the sidecar's hash binds those producer assertions to the checked ELF. If these requirements move into the C descriptor later, bump descriptor version/symbol and retain explicit rejection; do not enlarge version1 structures in place.

Each new title library exports only `recomp_module_descriptor_v1` as a dynamic data symbol; optionally retain an explicitly versioned PGO interface when used. Remove the legacy `lasgame_tables` getter from the common producer instead of presenting upstream ABI1 and3 behind one name. Keep generated functions/address/count arrays hidden. Verify symbol type, definition owner and immutable metadata in producer/ELF checks: generic `dlsym` can otherwise find a dependency's symbol. The existing generic loader does not prove ownership or pointer extents.

Keep `liblasgame.so` SONAME initially and `DT_NEEDED libmain.so`, linked with `--no-undefined`, `-Bsymbolic` and16KiB maximum segment alignment. The same filename currently points to different reference runtime bytes; that is not sharing. Add a runtime dynamic-export allowlist covering the union of actual generated imports, measured from both libraries. The [complete legacy audit](shared-aot-imports.md) now finds56 runtime names:9 execution/hook/profiling,9 SDK libc wrappers,37 LAS patch helpers and Eevee's scene callback. `rt_brk` is declared in source but absent from those final dynamic import sets; declarations and sampled-object imports are not a complete measured allowlist. Re-audit after recompilation before freezing the production exports. Inline ARM64 FP helpers need no dynamic export. Keep static dependency symbols hidden and registration sections retained.

The initial interface uses direct runtime symbols, including existing hook globals; a function-table-only API is a separate generation change. Give those symbols documented `shared-aot-v1` semantics rather than promising arbitrary internal exports. Check complete `DT_NEEDED`, imports, architecture, SONAME, segment alignment and metadata export for each output. Both libraries must link against the **same actual runtime**. Its runtime implementation may change without recompiling code when the frozen API/helper contract remains compatible; a different CPU/inline helper/hook semantic contract invalidates generated code.

## Title adapter split

Proposed `native/adapters/las/` owns `game_addresses.h`, `hle/hooks.c`, LAS version maps/randomizer/game-object patches, accepted input revisions/program IDs and save/input policy. `native/adapters/letsgo/` owns the Eevee/Pikachu map currently embedded in `fnhook.c`, `gamesetup.c` build policy, and registrations/object offsets in `hle/controller_skip.c`, `hle/wildbattle.c`, `hle/fps60.c`, `hle/cutscene.c` and related title features. Disable optional title enhancements during first comparisons. Each adapter supplies module specs, entry/init policy, canonical address maps and isolated save namespace; generic NPDM parsing stays core.

Generic loader/dispatch/kernel/threading, HLE registries, filesystem primitives, shared-font resource access, audio and NVN remain common. Import required Let's Go services such as `services/hwopus.c` as shared implementations, with the isolated Opus-enabled FFmpeg dependency and explicit unsupported-service diagnostics. Program ID, save routing and input defaults must come from the selected adapter/profile instead of LAS's hardcoded `svcGetInfo` answer or title-specific FS branches. Do not copy an entire renderer/service tree behind a title switch.

Separate semantic code identity from build-cache keys. Semantic identity covers execution ABI/helper headers, SIMD/hooks, generator/lifter/patch/HLE inputs, target and per-module originals/layout. Save paths/contents are never build cache outputs. Publish new private artifacts atomically into new directories; retain working references and their existing cache namespaces.

## Smallest implementation sequence and gates

1. Freeze `shared-aot-v1` headers/sidecar schema, exact CPU assertions and separate hook capabilities; retain provisional metadata tests. Add meaningful synthetic direct-call/cache-hit/indirect-call hooks, original-call bypass, instruction-hook branches, cache collision/isolation and two/four-module init-order cases. Test actual host and NDK headers; compile ARM64 musttail fixtures. No game rebuild needed for this seam.
2. Extract one LAS Android runtime with immutable session layout, generic module/init loops and both adapters' metadata. Prove both synthetic module profiles through its loader; wrong CPU/shift/caps/hash must stop before guest entry. Include reserve-failure behavior and required-import/registry retention checks. This is the first real shared execution seam, beyond a standalone descriptor gate.
3. Produce new LAS and Eevee entries/objects against that contract using existing verified generated C where unchanged; link both to the single runtime. Preserve original reference libraries/caches. Before a long rebuild, compile representative main/SDK/subsdk units and both entry objects, then audit imports and required helpers to catch union-API omissions cheaply.
4. Stage one hashed runtime for both sessions. Port required service deltas and renderer semantics individually, keeping the Android backend. Only after the owner finishes the manual session, reproduce each baseline route in fresh processes and verify the same loaded runtime hash. Compare controls, font/text, audio, transitions and save/reload; Eevee capture/battle and later GPU-store behavior remain separate gates.

The original dual-title blocker remains present in the legacy apps: LAS dispatch accesses beyond a1,024-byte Eevee CPU, its Android function-entry macro lacks Eevee's required hooks, and its compile-time shift fixes every core address to LAS. The new common CPU/hook contract, runtime session layout and four-module registry now resolve that design conflict in the synthetic execution foundation. Actual runtime consumers and game objects still need migration to it. Subsequent HLE/renderer/gameplay convergence is required; independent readable controller scenes and a successful link do not establish it.
