# Echoes rift and shadow rendering investigation

The owner's Castle Town File 2 exposed defects outside the initial scene acceptance: pale square artifacts, unexpectedly dark lighting and rift boundaries whose interiors still showed the ordinary world. Thirty presents per second did not establish correct rendering.

## Established failures and corrections

Both original `compute_shadowprojection.bfsha` variants needed VMNMX integer min/max followed by a returning 32-bit ATOM.ADD. The translator now supports the observed operations through real storage-buffer atomics. Both original shaders pass complete translation and SPIR-V validation; unsupported atomic operations remain explicit errors.

Executing those writes exposed a writable-mirror allocator failure. It stopped after eight idle victims despite reclaimable storage. The corrected allocator merges completed readbacks, reclaims with a progress bound, and waits only for older submissions with its mutex released. Pending work remains protected and stores are never discarded. The next Thor run passed the prior failure at 30 fps with zero skipped operations, while the visible defects remained.

A separate feedback path replaced valid one-layer depth-array snapshots with a dummy texture. It now creates an array view of the same real snapshot image. This alone did not resolve the visible rift.

The full rift material capture established the rift-specific defect: requests for depth and stencil views of the same combined image resolved to the same depth view. ProjectionMask, CrackInside and CrackWall shaders test raw stencil bits `0x20` and `0x40`. They require a stencil-aspect view, unsigned sampler and direct integer register results. Their render targets and producer/consumer chain were present; alpha testing and logic operations were not active defects in that capture.

The new path selects the effective view/texture stencil mode, uses distinct sampled depth/stencil views while retaining combined attachment views, and specializes shader keys, memoization and integer samplers. Integer filtering uses nearest sampling with separate cache entries; ordinary float sampling remains unchanged.

Stencil-only writers also failed to invalidate combined feedback snapshots. The corrected freshness check includes possible stencil writes and prevents depth-only self-write reuse when the draw samples stencil. This improved cache correctness but the next device retry still showed the missing interior.

An exact live 4,372-byte stencil-producing vertex shader then established another missing feature: its header declares ClipDistance0 and the instructions write that plane, but the translator dropped the output. Clip-distance support now follows the declared/written mask, initializes unwritten array elements neutrally and requires the enabled Vulkan capability. The subsequent Thor retry still showed the missing interior and speckles. A short move also reproduced a black world with the rift border, fountain water and smoke still visible. The exact-producer host test uses the existing generic BRX fallback to avoid an inherited optimizer read beyond the captured compiler-constant span; production BRX behavior is unchanged.

The inherited F9 pass-image capture forces submission during graphics mirror preparation and tripped the submission guard in a diagnostic run. It must not be used for this investigation. A separate bounded `stencil-probe.request` capture now queues stencil-only readbacks on the normal pending submission and retires them after completion, without flushing, submitting or waiting. It records feedback source/snapshot pairs and actual unsigned sampled stencil inputs, including nonattachment masks. The first device capture verified matching feedback source/snapshot histograms but did not reach the rift mask; that result does not qualify the mask. No readbacks occur without an explicit request.

A same-artifact diagnostic restart with native D24S8 confirmed driver support and made the initial saved scene brighter, but did not restore the rift interior or prevent the black world after movement. The option was restored afterward. This is evidence that depth representation affects rendering, not a complete fix. A later D24S8 retry with GPU-uniform forwarding and contiguous CPU uploads retained the small roof/pavement stippling; native depth selection alone is not its cure.

The asynchronous probe initially used the game producer present counter, which can advance ahead of renderer queue execution and expire a request before relevant draws. It now uses the renderer logical frame, with a regression advancing the counters independently and a bounded capture summary.

Device diagnostics also established that the three rift consumers see the same raw stencil plane: bit `0x40` forms character silhouettes, while bit `0x20` is absent. The original shader uses these as character exclusions, so the absence of a polygon in stencil is not a demonstrated defect. The ProjectionMask RGBA output is entirely zero, including alpha, while its input color texture contains the rift polygon; its other output retains the prior world-normal buffer. This narrows the missing interior to rejected/discarded projection fragments or their inputs.

A temporary EQUAL-depth tolerance experiment kept the world visible and removed most speckles after controlled movement, but still omitted the rift interior. Exact half conversion did not do so. A separate depth-copy optimization-off run also stayed visible after the same movement. A subsequent same-artifact baseline without these overrides also recovered after the movement. These short observations therefore do not establish causation; none is an accepted production accuracy fix. A strict-flush diagnostic likewise did not restore the rift interior.

The unread-history color alias shortcut independently violates copy lifetime: after two unread copies it could overwrite the source and later serve newer bytes for the earlier copy. The correction preserves pending copy contents before source overwrite, while retaining safe color aliases and depth/stencil handovers. An extracted-production regression reproduces the original failure and passes with the correction. Device visual benefit remains unqualified.

Fence auditing confirmed that `backend_execute` already submits every command list, including the pinned upstream implementation. Ordinary `IT_EXEC` fence mapping was therefore not a demonstrated early-completion bug; the initial negative model omitted that mandatory submission, and its earlier qualification is withdrawn. Ordered queue-fence markers additionally cover a narrower pending tail, such as alias-preservation GPU copies recorded during texture destruction without a subsequent list. A controlled destruction-tail model fails with the old marker behavior and completes with the correction; it does not establish that Echoes encountered this case. The corrected regression executes the actual `backend_execute` body and verifies that ordinary lists complete under both old and new mappings. Sync publication is atomic and monotonic on reuse, and Android defaults to strict GPU completion and mirror writeback. The historical one-frame lag remains an explicitly labeled research override. Existing finite SyncWait timeout behavior remains blocking; QueueFinish and QueueWaitSync are outside this correction. None of these changes is a proven visual cure.

## GPU-produced uniform handoff

An ordered GPU buffer readback at the same ProjectionMask draw established the missing handoff. Scene-buffer rows 33/34 contain the computed projection matrix in the writable GPU mirror, while the uniform staging snapshot sent to the shader contains identity rows. The actual sampler has a zero border. Original shader replay with that identity snapshot discards the mask, agreeing with the empty GPU RGBA output.

The original `compute_shadowprojection.bfsha` variant at asset offset `0x15000` writes these rows through storage buffer 0; other variants produce camera rows. This is a storage-to-uniform dependency. No write through a read-only uniform address needs to be assumed. The separate mask producer and consumer use different camera-buffer ranges, so replay of the old mask texture does not establish a texture-origin defect.

A general GPU-owned uniform forwarding path is now enabled by default (the explicit research value `LARECOMP_GPU_UNIFORM_FORWARD=0` disables it). It prepares GPU-owned uniform ranges before rendering, supports compute consumers, preserves explicit CPU updates in queue order, and protects mirror ownership until GPU completion. The first flagged File 2 load rejected a partial/multiple-owner range. A bounded CPU/GPU composition path then restored the visible purple rift interior, bright lighting and clear surfaces at 30 fps. Movement exposed overlapping persistent owners (320-byte ranges 256 bytes apart), so this was not accepted as stable gameplay. Conservative overlap consolidation and chronological readback merging then passed a short four-direction test. A longer recorded walk still reproduced loss of most opaque scenery at another camera position while the purple rift interior remained visible. The short test therefore does not qualify stable rendering. A separate actual-helper regression proves that CPU-diff upload coalescing can overwrite unchanged CPU words containing newer GPU results. The candidate now uploads only contiguous changed CPU words. Its first longer walk still blacked out during thousands of asynchronous program/pipeline build skips; the subsequent warm walk kept the world visible at approximately 30 fps with zero skipped operations. The older blackout also occurred with zero skips, so the two observations must not be conflated. Safe direct uniform reuse within an active render pass passed source review and host tests and reduced the measured rendering-pass overhead. Required graphics programs and pipelines now wait for first-use completion while worker compilation and background preparation remain asynchronous. A fresh ordinary Play run with experiment flags absent loaded File 2, rendered the rift interior, and passed the longer movement recording at approximately 30 fps with zero skipped operations. Small roof/pavement stippling remains unresolved; native D24 did not remove it. The identical default runtime also loaded LAS File 2 in Mabe Village and Eevee’s lab save, accepted short movement and stopped cleanly. These are bounded regression checks, not complete graphics or performance qualification.

## Explicit remaining compatibility limitation

A separate Common particle shader binds a stencil-selected combined image to a comparison instruction. Its intended low-level behavior is unqualified. To avoid introducing a new failure while correcting the proven raw-stencil path, comparison instructions retain the preceding float/depth behavior on the same real combined image and emit an explicit compatibility warning. This is preservation of inherited behavior, not a claim of accurate NVN semantics. Missing depth, intrinsic stencil-only images and dummy substitutions reject explicitly in that compatibility path.

## Validation and device gate

Asset-free optimized/sanitized checks cover numerical instruction results, returning atomic contention, actual mirror reclamation and readback lifetimes, view aspects and identities, integer samplers, typed shader keys and actual binding behavior. Android translation units compile. The three original raw-stencil fragment shaders pass SPIR-V validation; the Common shader test qualifies compatibility compilation only.

The current default runtime passes a bounded File 2 ordinary-launch and movement test, including the restored purple rift interior. It does not qualify all locations or resolve the remaining surface stippling. LAS/Eevee saved-scene regression passed on the same runtime; owner handoff remains pending. Private captures, original shader/resource matches, keys and save checkpoints remain untracked.

Ordinary Play also now clears diagnostic flags using actual LF/CRLF parsing. The old escaped regex retained those flags across launches, so final validation requires recording their absence; the new filter preserves title/package credentials, settings and driver preferences.

## Bounded surface-depth diagnostics

A separate request-only depth replay now copies effective attached depth and replays at most two selected opaque draws into a private R32 nearest-depth image using the already bound VS, descriptors and geometry. It does not submit, flush, wait for GPU work, or change production depth comparison. Readback retirement uses the normal completed sequence. Mixed coverage and occlusion remain explicit interpretation limits, and the private fragment pipeline can affect driver optimization.

The first measured shader family proved to be foliage, not the roof. A later original-resource match identified the actual orange roof as M_PBR_BG_RGB. Its measured roof region covered 32,498 pixels, all exactly equal to the effective depth buffer, including three golden-patch regions. This does not support an EQUAL-depth tolerance workaround for that roof. Pavement is not qualified by that measurement.

Bounded live CPU reads matched the roof's complete normal, material and albedo texture storage to original embedded assets. Production Tegra deswizzling independently agreed across all 30 mip levels. This excludes CPU texture corruption/layout for those buffers; GPU sampling, original-fragment shading and later composition remain separate questions. The original material contains authored variation, but the visible pattern has not been established as wholly authored.

## F32 and half arithmetic audit

The actual roof fragment shader exposed a separate translator error: F32 operands to half arithmetic were narrowed before the operation. A cancelling mixed add and an all-F32 FMA reproduced loss of an exactly representable nonzero result. The corrected GLSL paths preserve F32 operands, widen half operands where required, and convert results at the merge width established by the reviewed reference. Mixed operations round to half before merging; all-F32 operations returning F32 retain F32 output, while half-lane merges narrow afterward. Shadow-cache and guarded paths are covered. Unobserved ambiguous packed all-F32 mode and existing FTZ/FMZ behavior remain unchanged.

Actual-emitter numerical counterexamples, native/software variants, guarded execution, SPIR-V dataflow and both original roof half-shadow configurations pass. The host reference uses RTE; this alone does not qualify physical GPU rounding controls or establish that this error caused every visible surface patch. The fresh ordinary-launch Thor retry loads File 2 at approximately 30 fps with zero skipped operations and the rift interior visible. Small surface patches remain visible, so the arithmetic correction is not claimed as their complete cure. A 55-second eight-leg recorded movement test did not reproduce the large blackout, with recent steady Echoes samples at 30 fps and zero skipped operations. The old recording reproduces the blackout under the same video detector. Fresh LAS File 2 and Eevee lab sessions also loaded and accepted movement on the identical final runtime. Small surface patches remain unresolved; these bounded checks do not qualify every area or all graphics.
